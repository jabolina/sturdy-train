# Infinispan Resiliency Harness

A benchmark harness for reproducing and measuring Infinispan cluster degradation under fault injection.
It drives load against a containerized cluster while injecting faults (node stops, network partitions)
and collects client-side and server-side telemetry.

## Prerequisites

- Java 21+
- Maven
- Docker and Docker Compose

## Building

```
mvn package
```

## Quick Start

Start a 5-node cluster with monitoring:

```
./bin/cluster.sh
```

In a separate terminal, start the load driver:

```
./bin/run.sh --configuration scenarios/coordinator-failover.xml
```

Inject a fault:

```
./bin/coordinator.sh stop
```

## Cluster Management

`cluster.sh` generates Docker Compose and Prometheus configs, starts the cluster in the foreground,
and tears everything down on CTRL-C.

```
./bin/cluster.sh --size 3
./bin/cluster.sh --size 3 --java-opts "-Xmx3g -XX:+UseZGC"
./bin/cluster.sh --size 7 --image local/server:fix
```

## Load Driver

The driver creates a cache from an XML configuration file and runs continuous `put` operations.

```
./bin/run.sh --configuration <cache.xml> [options]
```

| Option             | Description                                      | Default           |
|--------------------|--------------------------------------------------|-------------------|
| `--servers`        | `;`-separated Hot Rod endpoints                  | `localhost:11222` |
| `--configuration`  | Cache XML file (required)                        |                   |
| `--keys`           | Key space size                                   | `5000`            |
| `--value-size`     | Payload size in bytes                            | `512`             |
| `--threads`        | Writer threads (closed-loop driver)              | `128`             |
| `--rate`           | Ops/sec target (selects open-loop driver)        | unbounded         |
| `--distribution`   | Key distribution: `uniform` or `zipfian`         | `uniform`         |
| `--duration`       | Run duration, e.g. `PT1M`, `PT30S`               | unbounded         |
| `--jfr`            | Enable JFR recording (consumed by `run.sh`)      |                   |

### Drivers

- **Default (closed-loop)**: ticket-based concurrency, bounded by `--threads`. Subject to coordinated omission.
- **Uniform (open-loop)**: fixed-rate metronome selected with `--rate`. Fire-and-forget virtual threads, records wait time for coordinated omission correction.

### Key Distributions

- **uniform**: keys drawn uniformly at random from `[0, keys)`.
- **zipfian**: scrambled Zipfian distribution. A small set of hot keys receives most traffic, but keys are permuted so popularity is independent of key value.

## Fault Injection

```
./bin/coordinator.sh find     # show cluster view and coordinator
./bin/coordinator.sh stop     # send SIGINT to the coordinator
```

## Observability

### Grafana

Available at `http://localhost:3000` (admin/admin) with pre-provisioned dashboards:

- Cluster size, JVM memory, GC overhead/pause rate
- Cache size, store rate, average write time
- Locks held, transaction rollbacks
- JGroups flow control blockings, Netty I/O pending tasks

### JFR (Client)

Pass `--jfr` to `run.sh` to record custom `CacheOperation` events on the driver.
A timestamped HTML report is generated automatically after the run.

```
./bin/run.sh --configuration scenarios/coordinator-failover.xml --jfr
```

Generate a report from an existing recording:

```
./bin/jfr-report.sh [path/to/recording.jfr]
```

### async-profiler (Server)

Attach async-profiler to all running server nodes at runtime.

```
./bin/asprof.sh start --path /path/to/async-profiler
./bin/asprof.sh start --path /path/to/async-profiler -- -e wall --all
./bin/asprof.sh stop
./bin/asprof.sh stop -- -o jfr
./bin/asprof.sh status
```

Output files are written to `logs/ispn-{N}/`.

## Cleanup

```
./bin/clean.sh              # server logs
./bin/clean.sh reports      # HTML reports and async-profiler output
./bin/clean.sh jfr          # JFR recordings
./bin/clean.sh all          # everything
```

## Project Structure

```
bin/                        Scripts
scenarios/                  Cache XML configurations for different test scenarios
infra/                      Server configuration (infinispan.xml, log4j2.xml)
grafana/                    Grafana provisioning (dashboards, datasources)
prometheus/                 Prometheus config (generated by cluster.sh)
logs/                       Runtime output (server logs, JFR, reports)
src/                        Load driver source
```
